# AI PM Interview Coach Skill

面向 AI 产品经理求职场景的 Codex Skill。它以“十年资深 AI 产品经理 + 严格面试评估者”的角色工作，支持面试准备、一次性题库、逐题模拟、真实面试复盘、后续轮次准备和长期表现分析。

## 核心能力

- 拆解公司、岗位、JD 与简历之间的匹配关系，识别项目追问点和风险点。
- 在没有 JD 时，基于公司、岗位名称和简历进行联网研究；来源不足时停止公司定向推断，而不是编造 JD。
- 一次性生成指定数量的问题，并给出考察意图、回答方向、参考答案与追问建议。
- 开展简历面、项目面、压力面、场景面等逐题模拟。
- 从用户明确指定的真实面试转写或录音中提取问题与回答，诊断啰嗦、重点不清、结论后置、证据不足等问题，并给出可执行的改写方案。
- 根据文本或可实际读取的音频证据分析面试官风格、追问逻辑和回答策略；不会把文本推断伪装成语气、语速或音调分析。
- 在用户明确指定材料范围后，分析多场真实面试的长期表现；模拟面试永远不会自动计入真实表现。
- 可选配 MediaCrawler，对用户明确授权的、范围受限的小红书面经搜索结果做文本优先、图片补充的证据分析。

## 关键边界

- 必须由用户显式调用 `$ai-pm-interview-coach`，不会因普通对话自动触发。
- 面试准备、模拟和题库模式必须同时具备公司、岗位名称与简历；缺少任一项时会先要求补充。
- 只读取用户明确提供或选择的文件、文件夹、转写和录音，不主动扫描工作目录。
- 只有用户明确指定为“真实面试”的材料才属于真实面试证据。模拟记录、文件名、目录名和历史对话都不能替代这一确认。
- 有录音扩展名不代表已经听取音频；输出会明确列出实际读取的材料、模态和不可用证据。
- 默认只在对话中返回分析。除非用户明确要求，否则不写入或修改复盘报告。
- 评价要求直接、客观、具体、可验证，不奉承，也不凭空补充候选人经历或业绩。

## 仓库结构

```text
.
├── ai-pm-interview-coach/        # 可安装、可分发的完整 Skill 目录
│   ├── SKILL.md                  # 入口与模式路由
│   ├── agents/openai.yaml        # Codex 展示与调用元数据
│   ├── references/               # 各模式的详细规则
│   └── scripts/                  # MediaCrawler 检查与小红书 JSONL 归一化工具
└── tests/ai_pm_interview_coach/  # 契约测试、脚本单测与行为验收场景
```

安装或发布时必须保留整个 `ai-pm-interview-coach/` 目录，不能只复制 `SKILL.md`；入口文件依赖 `agents/`、`references/` 和 `scripts/`。

## 安装

### 方式一：让 Codex 从 GitHub 安装

仓库推送到 GitHub 后，在目标电脑的 Codex 中明确要求：

> 请从 `<GitHub 仓库 URL>` 的 `ai-pm-interview-coach` 子目录安装 Skill。

安装完成后，重新开启一个任务，再显式调用 `$ai-pm-interview-coach`。

### 方式二：手动安装

1. 下载或克隆本仓库。
2. 将完整的 `ai-pm-interview-coach/` 目录复制或链接到本机 Codex Skills 目录下，并保持目录名为 `ai-pm-interview-coach`。
3. 重新开启一个 Codex 任务。
4. 输入 `$ai-pm-interview-coach` 并说明需要的模式。

## 使用示例

### 面试准备或一次性题库

```text
$ai-pm-interview-coach
公司：示例科技
岗位：AI 产品经理
简历：/绝对路径/我的简历.pdf
JD：没有，请联网研究
请一次性生成 10 道高概率问题，并提供回答方向、参考答案和可能追问。
```

### 逐题模拟

```text
$ai-pm-interview-coach
请基于我指定的公司、岗位、简历和 JD 开始项目面模拟，一次只问一道题；每题回答后先追问，再严格点评。
```

### 真实面试复盘

```text
$ai-pm-interview-coach
我明确指定 /绝对路径/一面带时间戳转写.md 是本次真实面试原文。
请只基于这份真实材料复盘，不要把之前的模拟记录计入真实表现。
```

### 后续轮次或长期分析

```text
$ai-pm-interview-coach
我即将参加二面。请使用我明确选择的一面真实转写和一面复盘作为背景，结合当前公司、岗位和简历准备二面。
```

## 可选的 MediaCrawler 配合方式

[MediaCrawler](https://github.com/NanmiCoder/MediaCrawler) 不包含在本仓库中，需要在每台电脑上单独安装、配置并遵守其许可与目标平台规则。Skill 不会替用户安装、自动登录、读取或复用 Cookie、绕过访问控制，也不会因为发现本地目录就自动启动爬取。

使用时需要：

1. 用户显式要求针对指定公司、岗位和关键词执行范围受限的小红书搜索。
2. 在当前请求中提供 MediaCrawler 的绝对路径，或自行配置 `AI_PM_MEDIACRAWLER_PATH`。
3. 先运行 Skill 自带的本地可用性检查；只有检查状态为 `ready`，且用户当前请求明确授权搜索时，才允许执行规则中限定的一次搜索命令。
4. 搜索产物保存在仓库外的临时目录中，默认不提交、不长期保存；文本和元数据先分析，只有实际提供了图片时才分析图片内容。

MediaCrawler 不可用时，Skill 会退回普通网页研究，并明确说明这不等同于本地小红书导出，也可能无法覆盖图片中的面经。

## 测试与校验

在仓库根目录运行：

```bash
python3 -m unittest discover -s tests/ai_pm_interview_coach -p 'test_*.py' -v
python3 -m py_compile \
  ai-pm-interview-coach/scripts/check_mediacrawler.py \
  ai-pm-interview-coach/scripts/normalize_xhs_jsonl.py
```

行为验收场景位于 `tests/ai_pm_interview_coach/behavior_cases.md`。

## 隐私与数据安全

简历、JD、面试录音、面试转写、复盘报告、爬取结果和登录数据都可能包含敏感信息。不要把这些个人材料提交到本仓库。仓库的 `.gitignore` 已屏蔽常见本地数据目录和录音格式，但提交前仍应检查 `git status` 与暂存区内容。
